# Данные Дошикологии

Каталог рассчитан на десятки и сотни рецептов без дублирования данных в JavaScript.

## Файлы

- `config.json` — версия приложения, баннер, CloudTips, порядок основных категорий и главный рецепт.
- `recipes.json` — единственный источник рецептов.
- `patrons.json` — записи Стены меценатов.

## Формат рецепта

Каждый рецепт должен иметь уникальный `id` и поля `title`, `description`, `time`, `difficulty`, `cost`, `ingredients`, `steps`, `story`, `image` и `categories`.

Новые категории автоматически появляются в интерфейсе после основных категорий из `config.json`.

**Правило названий:** во всех новых рецептах, историях, ингредиентах и текстах приложения используем только «Дошик» (с правильными падежными окончаниями). Не используем названия сторонних брендов лапши. Проверка запускается автоматически при изменениях на GitHub.

Перед публикацией каталог можно проверить командой:

```bash
node scripts/validate-data.mjs
```

## Даты публикаций и Стена

У каждого рецепта есть `publishedAt` — момент **первого появления** рецепта в каталоге (UTC или со смещением). Например:
`"publishedAt": "2026-10-11T14:30:00+09:00"`.
Уже опубликованному рецепту дату менять не нужно: исправления текста и фотографий не делают блюдо новым.

При добавлении рецепта обновляй `recipes.json`, `recipe-entries/<id>.json` и соответствующий `hash` в `recipes-index.json`, для индекса изменений и последующего переноса данных в Kotlin-версию. Новые пять рецептов на главной выбираются автоматически по `publishedAt` (если у нескольких дата одинаковая, побеждают добавленные позже в каталог).

Модерированные сообщения донатеров находятся только в `patrons.json`. Поле `date` может быть строкой `"11.10.2026"` или `"11.10.2026 14:30"`. Пример:

```json
{
  "name": "Алексей",
  "amount": "200 рублей",
  "text": "На новые исследования Института!",
  "date": "11.10.2026 14:30"
}
```

Комментарии сортируются автоматически от новых к старым. Редактировать рецепты для пополнения Стены не требуется.

## Новости института

Новости — отдельный файл `data/news.json`, изначально пустой массив `[]`. Формат новости:

```json
{
  "id": "pervaya-novost",
  "title": "Новая рубрика института",
  "text": "Короткая новость или объявление для главной страницы.",
  "publishedAt": "2026-10-11T15:00:00+09:00"
}
```

Добавляй такие объекты в массив с запятыми между записями. На главной показываются максимум три свежие новости по времени. Веб-версия подхватывает обновления после публикации GitHub Pages. Нативная реализация обновляется отдельно в Kotlin-ветке.

## Почта поддержки и ссылка на пожертвования

Публичные параметры лежат в **`data/config.json`**, который GitHub Pages публикует по адресу
`https://crossdoomdev.github.io/doshikologiya/data/config.json`.

- `supportEmail` — общий почтовый адрес поддержки (сейчас `""`; после создания ящика укажите адрес вроде `help@example.com`).
- `donateUrl` — действующая HTTPS-ссылка на добровольную поддержку проекта.
- `remoteConfigUrl` — публичный адрес этого JSON-файла. Его важно оставить неизменным.

После изменения `supportEmail` или `donateUrl` и публикации GitHub Pages веб-версия получает новые значения при следующей загрузке страницы. Поле `remoteConfigUrl` оставляем для совместимости с отдельно выпускаемой Kotlin-версией, которая может использовать этот публичный адрес.

Если `supportEmail` пуст, ссылка «Написать разработчику» скрыта; при указании действительного адреса она появится. В `config.json` нельзя размещать пароли, API-ключи и другую секретную информацию: файл доступен всем.
