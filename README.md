# Дошикология

Статическое веб-приложение «Институт дошикологии».

**GitHub Pages:** https://crossdoomdev.github.io/doshikologiya/

## Архитектура

Проект подготовлен к каталогу из 50–100+ рецептов. Рецепты хранятся отдельно от интерфейса и JavaScript и имеют один источник истины.

- `index.html` — разметка.
- `images/ui/heart.svg` — единый SVG для всех сердечек на кнопках; заливка состояния определяется CSS.
- `css/styles.css` — стили.
- `data/config.json` — конфигурация, версия и CloudTips.
- `data/recipes.json` — единственный источник рецептов.
- `data/patrons.json` — Стена меценатов.
- `js/core/` — загрузка данных, состояние, маршрутизация, избранное и утилиты.
- `js/features/` — рецепты, модальное окно, готовка, Оракул, донаты и Стена меценатов.
- `js/main.js` — точка входа.
- `scripts/validate-data.mjs` — проверка каталога и пользовательских текстов на сторонние торговые названия.

JavaScript переведён на ES-модули с явными `import`/`export`. Новые категории из рецептов обнаруживаются автоматически. Поиск учитывает название, описание, историю, категории и ингредиенты.

Изображения рецептов используют относительные пути и не зависят от имени GitHub-репозитория. Текущая ссылка CloudTips сохранена в `data/config.json` и позже меняется в одном месте.

CSS пока оставлен единым файлом намеренно: текущий объём ещё удобен для поддержки и не требует искусственного дробления.


## Интерфейс и motion

- При запуске показывается короткая фирменная заставка с полным логотипом Дошикологии. На главной странице он больше не дублируется. Для значка браузера, PWA и будущего Android-ярлыка используется отдельная иконка только с чашей, без нижней надписи.
- Интерактивные кнопки и нижняя навигация дают мгновенный визуальный отклик на касание без вибрации.
- Модальное окно рецепта и режим готовки появляются через короткие fade/slide-переходы.
- Оракул использует три состояния нарисованного мага лапши (прозрачные WebP без подписей и рамок): ожидание, колдовство и радостное вручение рецепта. Один локальный Web Audio сигнал воспроизводится после предсказания и при завершении готовки; никаких сетевых аудиофайлов или вибрации.
- Учитывается системная настройка `prefers-reduced-motion`.
- Для будущего Android-приложения визуальный splash останется резервным веб-слоем, а нативный экран запуска будет настроен через Capacitor/Android.

## Вкладка «Ещё» и юридическая документация

Пятая вкладка `#more` содержит проверку/загрузку рецептов (перенесена из «Протоколов» без изменения логики IndexedDB), сведения о версии приложения, поддержку и документы. Категории и поиск остаются только в «Протоколах».

Два статических документа доступны по постоянным адресам `privacy.html` и `terms.html`. `scripts/prepare-android.mjs` включает эти страницы внутрь будущей APK, чтобы они открывались без интернета. Юридические страницы пока являются **предрелизными проектами**: перед подачей в RuStore надо заполнить сведения о разработчике, проверить работу внешних сервисов и согласовать текст.

В `data/config.json` добавлено поле `supportEmail` (пустое до получения рабочего адреса). Как только в него будет вписан действующий адрес, на вкладке «Ещё» автоматически появится кнопка для личного обращения по электронной почте. Публичный GitHub Issues не используется как канал поддержки. Обращения принимаются только по электронной почте. В Android-версии Capacitor в режиме готовки подключён рекламный баннер РСЯ; добровольная поддержка осуществляется через CloudTips.

### Реклама в Capacitor / WebView

Блок `R-M-20184115-1` находится под описанием шага и над кнопками «Назад» / «Дальше». Локальный плагин `plugins/cooking-ads` подключает Yandex Mobile Ads SDK 8.5.0 автоматически при `npm install` и `npx cap sync android`, в том числе во всех существующих Android workflow. Каталог и готовка по-прежнему работают офлайн; при ошибке загрузки рекламное место скрывается.

HTML резервирует место, а нативный баннер привязывается к координатам этого места в WebView. Он скрывается во время прокрутки, вне видимой области и в фоне, освобождается при выходе или завершении готовки. Переход между шагами не создаёт новый рекламный запрос. Веб-сайт и Kotlin preview этот плагин не запускают.

Для проверки на устройстве используйте демонстрационную сборку: из каталога `android` запустите `./gradlew assembleDebug -PdoshikAdsDemo=true`. Она использует официальный `demo-banner-yandex`. Обычная сборка, включая debug, использует предоставленный `R-M-20184115-1`. Не проверяйте клики на боевых объявлениях. Реальная выдача зависит от активации блока и настроек приложения в РСЯ.

Документация SDK: [интеграция](https://ads.yandex.com/helpcenter/en/dev/android/quick-start), [inline-баннер](https://ads.yandex.com/helpcenter/en/dev/android/adaptive-inline-banner).

## Подготовка к офлайн-работе Android

В будущей Android-сборке встроенные файлы `data/recipes.json`, интерфейс и изображения будут доступны без интернета. `js/core/offline-catalog.js` сохраняет обновлённый каталог и изображения в IndexedDB. Источник каталога — поле `remoteRecipesUrl` в `data/config.json`. При запуске Android **не запрашивает удалённые рецепты**: используются встроенные и ранее сохранённые данные. На вкладке «Рецепты» пользователь вручную нажимает «Проверить обновления». Если найдены новые или изменённые рецепты, появляется отдельная кнопка скачивания. До подтверждения скачивания IndexedDB не изменяется, а при отсутствии обновлений карточки не перерисовываются. Веб-версия по-прежнему загружает свои начальные JSON-файлы с GitHub Pages как обычный сайт. Перед Android-релизом базовый комплект можно сократить до нескольких рецептов, а остальные загружать с сервера.

Веб-версия остаётся средой разработки: запуск самой веб-страницы без интернета потребует отдельного service worker, который пока не добавлен. Офлайн-хранилище также не исключает очистку данных пользователем или системой; для Android потребуется окончательная проверка устойчивости хранения и индикации завершения синхронизации.

## Обмен рецептом

Кнопка «Поделиться протоколом» открывает системное меню отправки, а при отсутствии такой возможности копирует юмористический текст и ссылку вида `?recipe=<id>#recipes`. При открытии ссылки показывается нужный рецепт.

**Решение по размещению:** GitHub Pages (`https://crossdoomdev.github.io/doshikologiya/`) — постоянный бесплатный адрес проекта и будущая посадочная страница Android-приложения. Свой домен и платный хостинг не нужны, адреса в `js/features/sharing.js` не меняем. После выхода приложения в RuStore добавляем сюда кнопку установки. Ссылки на рецепты продолжат работать в браузере.

Автоматический переход по HTTPS-ссылке непосредственно в установленное Android-приложение — отдельная необязательная функция. Для проверенных Android App Links потребуется разместить `/.well-known/assetlinks.json` именно в корне используемого хоста, чего не позволяет сделать один только проектный путь `/doshikologiya/`. Если когда-нибудь решим её добавить, можно рассмотреть бесплатный пользовательский сайт `CrossDoomDev.github.io` на том же хосте; пока достаточно веб-ссылки с возможностью установки, без дополнительных доменов и сервисов.

## Каталог из 50 рецептов и дельта-обновления

- `data/recipes.json` остаётся общим каталогом для сайта, офлайн-комплекта Android и старых версий APK.
- `data/recipes-index.json` содержит только идентификаторы, контрольные отпечатки и адреса отдельных записей.
- `data/recipe-entries/<id>.json` — отдельные файлы рецептов. При проверке новые APK скачивают **только индекс**, а после согласия пользователя — только отсутствующие или изменённые записи.
- Для изменённых рецептов загружаются только недостающие изображения в IndexedDB. Поскольку изображения имеют версионированные адреса, старые не скачиваются повторно.
- После перезапуска Android остаётся офлайн-доступ. Старые APK продолжают получать полный JSON из прежнего URL, но изображения уже кешируются поштучно.
- При редактировании рецепта необходимо обновлять общую запись, отдельный JSON и соответствующий отпечаток в индексе; автоматическая проверка CI не даст опубликовать несогласованные данные.
- Все 50 рецептов используют отдельные оптимизированные WebP-фотографии. Состав блюда на фотографии должен соответствовать списку ингредиентов: никаких лишних гарниров и украшений. Старые SVG-заглушки и их генератор удалены.


## Юмор и тематические истории рецептов

Категории задают не только фильтрацию, но и тон описания и историю блюда: «Вахтовое» — смены, бригады и жизнь на вахте; «Студенческое» — общага, стипендия, зачёты; «Холостяцкое» — самостоятельная готовка и минимум посуды; «До зарплаты» — экономия; «После зарплаты» — доступные маленькие гастрономические праздники; «Завтрак» — утренние заботы; «Острое» — игровая пожарная тревога. При нескольких категориях можно сочетать мотивы, не добавляя ингредиенты, отсутствующие в списке.

Все 40 дополнительных рецептов и тематически не подходившие истории оригинальных блюд переработаны вручную. Повторяющихся заключительных фраз в шагах нет. `scripts/validate-data.mjs` проверяет согласованность каталога с индексом, наличие фотографий, отсутствие лишних файлов и точных повторений описаний, историй и шагов. Нижняя граница количества — 50 рецептов; новые рецепты сверх неё поддерживаются.


## Контроль локальных ссылок и восстановление изображений

`node scripts/validate-data.mjs` дополнительно сверяет все статические ссылки HTML, CSS, JS-импорты, изображения Oracle, ресурсы манифеста и ссылки на каталог с файловой структурой. Неопубликованные или переименованные файлы останавливают GitHub Actions до публикации. Работу внешних ссылок (CloudTips) нужно проверять отдельно.

При ошибке изображения браузер подставляет встроенный логотип без бесконечных повторных запросов; при отсутствии прежнего файла в Android сохранённый рецепт использует актуальное комплектное фото того же блюда. Старые уже установленные APK невозможно изменить задним числом: при обновлении рецептов они должны скачать новые ссылки на фотографии.

## Лента свежих рецептов и новости

На главной вместо шести больших карточек — компактная лента пяти последних рецептов по их постоянной дате публикации `publishedAt`. При равной дате недавно добавленная запись выше. После ручной синхронизации рецептов в Android лента обновляется из актуального каталога. Во всех карточках есть дата, а время в формате ISO отображается в часовом поясе устройства.

Стена меценатов сортирует `data/patrons.json` по указанному `date`: `ДД.ММ.ГГГГ` или `ДД.ММ.ГГГГ ЧЧ:ММ`. Ручная перестановка комментариев не требуется. Для будущих новостей подготовлены отдельные `data/news.json`, интерфейс на главной и проверка схемы; новости пока пусты и не синхронизируются вместе с обновлениями рецептов в Android.


## Индикация обновления рецептов

Кнопка «Проверить обновления» запускает только ручную проверку индекса. Пока выполняется сетевой запрос, крутится индикатор, кнопки временно заблокированы, прогресс-бар показывает неопределённую стадию. Если новых рецептов нет, об этом сообщается отдельно.

При нажатии «Получить обновление» отображается фактический прогресс получения JSON-файлов и изображений (обработано X из Y); ранее сохранённые фотографии тоже учитываются как обработанные. Проценты относятся только к текущему этапу, а не к байтам передачи. На стадии сохранения показывается неопределённый прогресс; после успешной записи — «Готово». При ошибке можно повторить загрузку. Сетевые запросы JSON имеют таймаут 30 секунд, фотографии — 60 секунд (в браузерах с поддержкой `AbortSignal.timeout`). Анимации отключаются или упрощаются при `prefers-reduced-motion`.

Индикация реализована в общей веб-части, которая будет упакована в следующую Android APK. Для уже установленных APK потребуется новая сборка.
